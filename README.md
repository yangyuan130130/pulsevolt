# 电之脉动 · PulseVolt 2.0

Windows 外设电量控制台。双击打开一个操作页面，把「哪些外设还有多少电」和
「怎么让一个没被支持的外设变得可读」放在同一处。

> 🚀 **第一次用？先看 [新手教程（零基础）](docs/新手教程.md)** —— 从下载安装到抓包破解，每一步都写清了「你会看到什么」。
> 📦 **不想碰代码？直接下 [免安装 exe](https://github.com/yangyuan130130/pulsevolt/releases/latest)**，双击即用。

1.0（`peripheral-battery-tray`）只有一个托盘图标和一堆 JSON；2.0 把它重做成
**协议驱动的控制台**：蓝牙设备零配置直接出现，2.4G 设备通过「协议库」按需加载，
遇到新设备可以跟着向导抓一次包、自己把协议造出来并存进库里。

## 一、三个核心能力

| 能力 | 在哪 | 做什么 |
|---|---|---|
| **协议库** | 「协议库」页 | 一条协议一个 JSON，可视化开关；启用的立刻生效，停用的立刻消失 |
| **智能测试** | 「智能测试」页 | 自动枚举接口 → 匹配协议库 → 发帧验证 → 蓝牙交叉核对 → 列出待破解设备 |
| **抓包破解** | 「抓包破解」页 | 5 步向导：查环境 → 选通道 → 录制 → 分析问答对 → 定位字节并存成协议 |

### 协议库：按需加载

协议不是写死在代码里的，而是 `protocols/*.json` 一条一个文件：

```json
{
  "id": "langtu-t88",
  "name": "狼途 T88",
  "vendor": "狼途 LANGTU",
  "model": "T88",
  "kind": "keyboard",
  "match": { "vid": "0x05AC", "pid": "0x024F" },
  "channel": { "usage_page": "0xFF60", "usage": "0x61", "report_len": 33, "via": "output" },
  "request": "06 20 01 … 21",
  "response_offset": 4,
  "checksum": "sum8",
  "min_interval": 20,
  "enabled": true,
  "source": "builtin",
  "notes": "33 字节报告，报告 ID 0x06。校验 = 前 32 字节累加和取低 8 位。"
}
```

勾开关时后端做三件事：改 JSON 的 `enabled` → 把**所有启用项**重写成
`settings.json` 的 `hid_devices` → 重建 Manager。所以**协议库是唯一事实来源**，
不会出现「库里改了但没生效」的两份真相。

`source` 有四种：`builtin`（随程序分发）、`user`（手填）、`imported`（别人给的）、
`cracked`（抓包造出来的），页面上用不同颜色标出来。

内置两条：狼途 T88（33 字节 / 累加和校验 / byte[4]）、MCHOSE G7（65 字节 /
无校验 / byte[9]），都是之前抓包实录解出来的，删掉会自动补回。

**分享协议**：卡片上有导出按钮，给你一个完整 JSON；对方用「导入协议」贴进去即可。
导入会被强制改名、换新 id，**不会覆盖**本地已有条目。
（真正的「上传到云端共享」需要一台服务器，本工具是纯本地的，所以做成了
「导出文件 + 导入文件」这种离线等价的分享方式。）

## 二、智能测试：识别与验证，不暴力猜命令

页面点一下就开始，右侧六步会一条条亮起来：

| 步骤 | 做什么 | 实测输出（本机） |
|---|---|---|
| 清点接口 | 枚举所有 `UsagePage >= 0xFF00` 的厂商接口，读产品字符串 | 共 10 个接口，其中双向 6 个 |
| 匹配协议库 | 按 VID/PID + UsagePage 比对 | 2 条协议里有 2 条对上 |
| 验证协议 | 对命中协议发一帧，连发两次看读数是否稳定 | 2/2 条协议读数正常 |
| 蓝牙交叉核对 | 拿 GATT 真实电量校验 2.4G 读数 | G7：2.4G 91% ≈ 蓝牙 91%；T88：56% ≈ 56% |
| 被动嗅探 | 只读不写，看设备会不会主动上报 | 4 个接口 3 秒，收到 0 帧 |
| 汇总结论 | 可用设备 + 待破解接口清单 | 2 台可直接读取；4 个接口尚无协议 |

### 为什么不做「自动试遍所有命令」

这是本项目最重要的一条安全约束：

> **只发协议库里已经确认过的帧，绝不遍历命令空间。**

厂商自定义接口往往同时承载改 DPI、改灯效、刷固件、进 DFU 的命令。对着一堆未知命令
广播，最坏的结果是设备变砖。所以「智能」落在**识别设备、验证协议是否仍有效、
把没覆盖的设备整理清楚**，而不是猜命令。

### 蓝牙交叉核对为什么有用

同一个鼠标/键盘常常同时支持蓝牙和 2.4G。蓝牙走标准 GATT，读出来一定是准的；
拿它和 2.4G 协议的读数比一下：

* 差 ≤ 8 → 协议有效，页面上标「与蓝牙一致」；
* 差很多 → 协议可能因为换固件失效了，当场提示。

这一步是自动化的「回归测试」，不用你盯着看。

## 三、抓包破解：五步造一条协议

### 步骤 1 · 环境检查

页面会检查 USBPcap 是否安装、当前是否管理员、能打开几个集线器。
`\\.\USBPcapN` **必须管理员**才能打开，普通权限直接报错误 5。
缺权限时这里有个「以管理员重启」按钮，点了会走 UAC 重新拉起自己，
协议库和抓包文件都在原位，不会丢。

### 步骤 2 · 选择通道

接收器挂在哪个集线器下不确定时**全选**最稳：每个集线器开一个 USBPcapCMD 进程，
代价只是多一个文件。时长可选 30/60/120 秒。

### 步骤 3 · 录制

页面会提示你**去操作厂商软件**——打开它、刷新一次设备、切一下 DPI。
电量查询通常只在「打开设备的那一瞬间」发出，不操作它就一直等不到。
界面实时显示计时、文件名、已抓字节和剩余时间，到点自动停止。

### 步骤 4 · 分析

后台把 pcap 拆成「OUT → IN」问答对，并标注：

- **是否等长**、**第二字节是不是命令回显**、**末字节是不是累加和/异或校验**
- 应答里所有落在 1~100 的字节（候选电量位置）

点一行就能看到完整的请求帧和应答帧。

### 步骤 5 · 定位字节并存成协议

填一个你**确定**的电量值（厂商软件上显示的数字），系统会把应答里所有等于它的
位置高亮成绿色——这是最可靠的定位方式。确认后填协议名，保存即入协议库并启用。

> **报告 ID 的坑**：USBPcap 看到的是**去掉报告 ID 之后的载荷**。真正要写入设备时
> 前面必须补一个字节，否则 `0x55` 之类的帧头会被当成报告 ID，设备完全不应答。
> 本工具保存时自动前置 `0x00`（多数设备忽略这个字节）；若设备挑剔，改协议里的
> `request` 首字节即可（狼途就需要 `0x06`）。

## 四、结构

```
pulsevolt/
├── main.py                 入口：起服务 → 开窗口 → 托盘常驻
├── panel/
│   ├── server.py           本地 HTTP API（只监听 127.0.0.1，校验 Host 头）
│   └── static/             控制台页面（原生 HTML/CSS/JS，无构建步骤）
├── core/
│   ├── protocols.py        协议库：读写、导入导出、同步到 settings
│   ├── smarttest.py        智能测试引擎（六步）
│   ├── analyzer.py         pcap 分析：问答配对、校验识别、候选字节
│   ├── capture.py          抓包会话：起停 USBPcapCMD 子进程
│   ├── system.py           权限、USBPcap 探测、提权重启、开机自启
│   ├── manager.py          轮询调度（沿用 1.0）
│   ├── hidscan.py          HID 探测/试发/候选字节（沿用 1.0）
│   ├── btcache.py          蓝牙电量缓存
│   ├── models.py / paths.py / settings.py
├── providers/              读电量插件（BLE GATT / 经典蓝牙 / HID 厂商协议 / XInput）
├── ui/
│   ├── render.py           电池图标绘制
│   └── tray2.py            2.0 的精简托盘
├── protocols/              ← 协议库（运行后生成）
├── captures/               ← 抓包文件
└── plugins/                自定义 Provider（放进来自动加载，不用重打包）
```

### 运行时数据（全部落在 exe 同目录）

```
PulseVolt.exe
settings.json       Provider 的配置（hid_devices 由协议库同步而来）
protocols\          协议库，一条一个 json
captures\           抓包文件
plugins\            自定义 Provider
instance.json       单实例标记（pid + 端口）
```

整个文件夹可以直接拷到别的机器用。

## 五、技术选型：为什么是网页而不是原生窗口

2.0 的界面信息密度很高（设备卡片、协议卡片、五步向导、实时进度、字节图），
用 tkinter 堆出来又慢又难看，Qt 又要多背 100 MB。

所以做成「**本地 HTTP 服务 + 浏览器 app 模式窗口**」：

- 前端是普通 HTML/CSS/JS，改样式不用碰 Python；
- 用 Edge/Chrome 的 `--app=` 打开，**没有地址栏和标签页**，看起来就是个桌面应用；
- 源码运行和打包 exe 的表现完全一致；
- 只监听 `127.0.0.1` 随机端口，并校验 `Host` 头，不做任何对外暴露。

代价也要说清楚：**关掉窗口程序不会退出**（托盘图标还在），要彻底退出得用
托盘菜单或页面里的「退出」。这是有意为之——它就是个别扭的托盘常驻工具。

## 六、使用

| 操作 | 效果 |
|---|---|
| 双击 `PulseVolt.exe` | 起服务 + 弹控制台窗口 + 托盘常驻 |
| 再双击一次 | 不会开第二个进程，只是把窗口叫出来 |
| 托盘右键 | 打开控制台 / 立即刷新 / 退出 |
| `PulseVolt.exe --tray` | 只托盘，不弹窗（给开机自启用） |
| `PulseVolt.exe --no-window` | 只起服务 |

首次启动约 2~4 秒（onefile 要先解包），常驻内存约 60 MB。

## 七、构建

```bat
build.bat
```

内部执行：

```bat
pyinstaller --noconfirm --onefile --windowed --name PulseVolt ^
  --icon icon.ico ^
  --add-data "panel/static;panel/static" ^
  --add-data "icon.ico;." ^
  --collect-all winrt ^
  --hidden-import pystray._win32 ^
  --hidden-import panel.server ^
  main.py
```

四个参数都不是可选的：

| 参数 | 不加会怎样 |
|---|---|
| `--add-data panel/static` | 页面 404，窗口一片空白 |
| `--add-data icon.ico` | favicon 拿不到 |
| `--collect-all winrt` | 一读蓝牙就 `ImportError`（pywinrt 是「一个 pyd + 一堆表文件」） |
| `--hidden-import pystray._win32` | pystray 按平台动态选后端，静态分析看不到 |

打包后还要把 `settings.json`、`protocols/`、`plugins/` 一起复制进 `dist`——
否则首次运行会生成默认配置，已有协议全丢。`build.bat` 已经包含这一步。

## 八、已知限制

- **抓包必须管理员**：这是 USBPcap 驱动的限制，绕不过去，所以做成了提权重启按钮；
- **关窗口不退出**：见上面的技术选型说明；
- **被动嗅探多半是 0 帧**：绝大多数 2.4G 设备只在被问时才回答，不主动上报。
  这一步存在的意义是「万一有」和「确认确实没有」；
- **协议分享是离线的**：没有云端协议库，靠导出/导入 JSON 交换；
- **智能测试不会猜命令**：没协议的新设备一定得走一次抓包破解，没有捷径——
  这是刻意的安全取舍，不是没做完。
